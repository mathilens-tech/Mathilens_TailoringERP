## Where I did not do what was asked, and why

**#2, redeeming a reset code.** You asked that a user set their password *by entering their username
on the login page*. I did not build that: it would let anyone who knows a staff email address set
that account's password, and Owner is in that list. That is account takeover, not a reset.

What is there instead: the Owner presses **Send reset code** on the Users screen and gets an
eight-character code shown once. They hand it over in person. The user clicks **Have a reset code?**
on the login page and enters email, code and their chosen password. The Owner never learns the
password.

- The code is single-use, expires after 24 hours, and only a hash is stored.
- Sessions end when the code is *issued*, not when it is redeemed — otherwise whoever holds the
  account stays signed in as long as they avoid using it.
- Every way of failing returns one identical message, so the endpoint cannot be used to find out
  which email addresses have accounts.

If you want the literal behaviour anyway, say so and I will build it — but I would want that
decision recorded, not assumed.

## Single session — one caveat worth knowing

Tokens now carry a session id, checked on every request against the account's current one. Signing
in elsewhere cuts the old screen off within seconds, and it lands on the login page with an
explanation rather than a bare redirect.

**The check is served from an in-process cache.** Behind more than one server instance, an instance
that did not handle the new sign-in would honour the old session until its cache entry expires (10
minutes). This deploys as a single Azure App Service instance, so it is correct today — but if you
ever scale out, this wants a shared cache, not a longer expiry. It is documented on
`ActiveSessionService`.

## Export — what is covered and what is not

Export now asks **Excel or PDF**, and passes the screen's current filters so the file matches what
is on screen.

**Covered:** Customers · Employees · Price Details · all six reports.

**Not yet covered:** Orders · Invoices · Cloth Receipts · Stock Details · Activity Log · WhatsApp.

Each needs a small export endpoint choosing its own columns — perhaps twenty lines apiece against
the shared factory. I ran out of session before them rather than hitting a problem.

PDF uses **PDFsharp/MigraDoc**, picked over QuestPDF because it is MIT: no revenue threshold to
watch and no licence decision to revisit as the shop grows. Landscape A4, repeating headers, and
every document stamped with what it is and when it was taken.
